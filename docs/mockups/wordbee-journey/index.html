TWB Platform × Wordbee: the admin journey

These pages show what an admin (and the linguist) would see when a project is created through the Wordbee option on project/{org_id}/create/, as the code on branch t_home_ngo works today. They are static mockups for discussion, made with sample test content and made-up people and organisations, not screenshots.

How to read these pages

  • The orange-topped cards are TWB Platform screens.
  • Blue boxes explain what happens behind the scenes (API calls, saved data).
  • Orange boxes and GAP tags mark places where the current code falls short or where details are unknown.

Gaps found while building this mockup

  • Wordbee's editor screen: I haven't seen it (the docs' screenshots weren't viewable here, and there's no Wordbee account). Step 5 is a generic illustration of a translation editor, not Wordbee's real interface.
  • Wrong button label: the linguist's task page says "Translate using Phrase TMS" for Wordbee tasks too (step 4).
  • No Sync or "View in Wordbee" buttons: the project page only shows "Sync Phrase TMS" and the Phrase link for Phrase projects, so admins can't trigger a sync by hand (step 3).
  • Metrics aren't shown: Wordbee word counts and match bands are saved but not displayed anywhere in TWB (step 6).
  • Unconfirmed API details: things like how long Wordbee takes to import, the job id format and the deliverable timing are based on the docs only (see docs/wordbee/README.md, Step 0).
